# EPIC-009: MQL Query Execution & Dynamic Output Label

## Goal

Enable users to **execute generated MongoDB Query Language (MQL) queries directly
from the Eng2SQL UI**, removing the current hard-coded placeholder message
_"MongoDB query execution is not yet supported"_ and delivering the same
point-and-click execute experience that MySQL and PostgreSQL users already enjoy.

A second, related UX improvement ships in the same epic: the right-side output
panel label and copy-hint text update **dynamically** based on the selected
database type — showing "Generated MQL" when MongoDB is active and "Generated SQL"
for relational databases.

---

## Business Value

- Users connecting to MongoDB can now close the full loop — write a question,
  get a MQL query, and immediately see the results — without leaving the app.
- Consistent UX parity: MySQL, PostgreSQL, and MongoDB all provide the same
  generate → execute → view-results flow.
- The dynamic label eliminates confusion (SQL panel for a MongoDB database).

---

## Scope

### In scope

| #   | Deliverable                                                                                                                                                                                                  |
| --- | ------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------------ |
| 1   | `MongoQueryExecutor` service — parses a structured MQL JSON string generated by the LLM, validates the collection name and pipeline, executes `collection.aggregate(pipeline)` and returns a `pd.DataFrame`. |
| 2   | LLM prompt update — add MongoDB-specific dialect tips to `sql_generator.py` so the model outputs a safe, parseable JSON object `{"collection": "…", "pipeline": […]}` instead of freeform JavaScript.        |
| 3   | Dynamic output label — `SQLOutputComponent.render()` accepts a `db_type` parameter; displays **"Generated MQL"** for MongoDB, **"Generated SQL"** for MySQL/PostgreSQL.                                      |
| 4   | Execute MQL button — `app.py` replaces the "not yet supported" info block with a **"▶ Execute MQL"** button; on click calls `MongoQueryExecutor`, stores results, re-renders the results table.              |
| 5   | Unit tests — ≥ 90% coverage on `MongoQueryExecutor`, coverage-preserving tests for `SQLOutputComponent` label change.                                                                                        |

### Out of scope

- Write operations (insert / update / delete / drop) from the UI.
- Support for raw JavaScript `db.collection.find(...)` shell syntax (security concern — no `eval`).
- Pagination UI for large result sets (target: first 100 documents by default).

## Acceptance Criteria

1. When the user selects **MongoDB**, connects, selects a database, and types a question,
   the right panel shows **"🗒️ Generated MQL"** (not "Generated SQL").
2. A **"▶ Execute MQL"** button appears below the generated MQL when a query exists and
   `mongo_db` is in session state.
3. Clicking the button executes the query; a `st.dataframe` of results appears below.
4. If execution fails (auth error, network, bad query), a clear `st.error` message is
   shown and no unhandled exception propagates.
5. The LLM prompt for MongoDB tells the model to output a JSON object
   `{"collection": "…", "pipeline": […]}` — no freeform JavaScript.
6. `MongoQueryExecutor` rejects collection names that do not match
   `^[a-zA-Z0-9_.\\-]+$` with a `QueryExecutionError`.
7. `MongoQueryExecutor` caps results at **1 000 documents** (adds `$limit: 1000`
   if no `$limit` / `$count` / `$group` stage is present).
8. All existing tests pass; new unit-test suite ≥ 90% coverage on the new module.

## Technical Notes

### MQL JSON format (LLM output contract)

```json
{
  "collection": "audit_logs",
  "pipeline": [
    { "$match": { "action": "login" } },
    { "$sort":  { "ts": -1 } },
    { "$limit": 50 }
  ]
}
```

The executor parses this with `json.loads()` (no `eval`). It validates:
- `collection` is a non-empty string matching `^[a-zA-Z0-9_.\\-]+$`.
- `pipeline` is a list (may be empty for a full-collection scan).
- A `$limit` stage is appended automatically when none is present and none of
  `$count`, `$group`, `$facet`, `$bucketAuto` is the last stage.

### Security guarantees

- **No `eval()`, no `exec()`, no shell calls** in the executor.
- `json.loads()` is the only parser; malformed JSON raises `QueryExecutionError`
  with a user-friendly message.
- Collection name regex prevents path traversal and command injection.
- The executor calls only `aggregate()` (read-only by nature of the pipeline).
